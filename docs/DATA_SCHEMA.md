# Data schema

## Normalized packet CSV

Exactly three columns, with one row per observed IP datagram:

| Column | Meaning |
|---|---|
| timestamp | Seconds on the gateway capture clock, typically UNIX epoch seconds |
| length | Declared IPv4 total length or IPv6 payload length plus 40; includes IP headers |
| direction | `1` for test-device uplink, `-1` for downlink |

Input rows are stably sorted by timestamp. IP lengths can exceed the captured prefix; this permits header-only/snaplen-limited capture. No payload inspection, TCP reassembly, QUIC decryption, or flow attribution by server is performed. Non-IP traffic and packets not unambiguously involving the device are counted and excluded. Capture on one LAN-facing interface to avoid duplicate observations before/after forwarding. Both the phone's IPv4 and IPv6 addresses must be supplied if it uses both.

PCAPNG supports multiple sections, interfaces, timestamp resolution/offset options, and enhanced packet blocks. Timestamp-less simple blocks, obsolete packet blocks, unsupported link types, malformed headers and IPv6 jumbograms fail clearly. Tunnels/VPNs and monitor-mode 802.11 captures are outside the supported study. Use a gateway Ethernet/Linux cooked capture.

## Manifest CSV

| Column | Example / requirement |
|---|---|
| session_id | Unique pseudonymous identifier |
| scenario_group | Shared identifier for related scripts, recordings and profile variants |
| split | train / validation / test |
| date | Actual YYYY-MM-DD collection date; partitions use separate later dates |
| label | Joint service/mode class label |
| service | Actual service name; stable mapping per label |
| mode | voice / video |
| is_genai | 1 or 0 |
| profile | good / constrained / lossy |
| packet_file | Relative normalized CSV or CSV.GZ path inside the dataset directory |
| ready_time | Active-session start marker on the same clock as timestamps |
| duration | Actual recorded active duration; at least 30 seconds |
| provenance | Entire dataset real or entire dataset synthetic |
| device_id | Pseudonym, excluded from ML |
| app_version | Measured version/tier description, excluded from ML |
| capture_drops | Verified nonnegative capture-drop count |
| capture_sha256 | Optional raw-capture checksum, generated by registration |

The worksheet uses `planned_label` and empty measurement fields. Registration produces completed manifest rows. A partial manifest can grow, but validation/training requires all three partitions and every class in each.

## Features and models

Prefixes `volume_`, `size_`, `timing_`, `burst_`, and `direction_` form the feature allowlist. Descriptive statistics include mean, population standard deviation, minimum, quartiles, 95th percentile and maximum. A burst is separated by an inter-packet gap greater than the fixed threshold, computed for aggregate traffic and each direction. Windows include their start and exclude their end: `[ready_time, ready_time + horizon)`.

`audit.json` records provenance, manifest/packet/feature hashes, partition sizes and parameters. Model bundles retain ordered feature names, horizon, threshold, sklearn version, class metadata and provenance. JSON prediction scores are uncalibrated. A synthetic model cannot classify an input declared as real.
